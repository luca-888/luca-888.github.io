# 去 AI 腔改稿

在草稿写完之后单独做这一遍，不和写作同时进行。边写边守风格规则效果差，因为注意力在内容上；写作者本人改稿还会替自己的句子辩护。所以最好交给一个新的 subagent，只给它文章路径和本文件，不给写作过程的上下文。

这几类套路的共同问题：句子在表演“讲解”，而不是在讲解。读者读到的是语气和姿态，信息却没有增加。删掉之后，文章更短，结论更直接。

## 要压制的套路

### 1. 先卖关子再揭晓

用一句短句加冒号吊胃口，再给出内容。直接说内容。这种句式偶尔用一次有力，每节都用就成了模板，读者很快会认出来。

| 原句 | 改后 |
| --- | --- |
| 量化问的只是一件事：每个数能不能少用几个 bit？ | 量化就是让每个数少用几个 bit。 |
| 问题出在两处：刻度等距，而数挤在零附近；一个 scale 管整层…… | 刻度等距，而数挤在零附近；一个 scale 管整层…… |
| 只有 16 个刻度这一点改不了。还能决定的只有两件事： | 刻度数固定为 16 后，可调的是刻度位置和舍入方向： |

同类：“答案是……”“原因很简单：”“关键就一点：”“X 做的事情只有一件：”“那么问题来了”以及自问自答的反问句。

### 2. 路标句

预告下文、回指章节、宣布“下面讲什么”的句子。读者会自己往下读，章节标题已经说明了结构，这些句子不带新信息，整句删掉；删后衔接不上时，用内容本身过渡。

例：“下文从一个数怎么存讲起，推到 FP8、NVFP4、GPTQ，最后看……”“第二到四节讲这件事”“下面两节分别改这两处”“接下来我们看……”“回到开头的问题”“前面提到……”。

章节内的步骤编号、图注里的“下图”可以保留。

### 3. 刻意的戏剧感

给事实加情绪或悬念的副词、短语、评价。科普文章靠具体数字和机制说服读者，外加的情绪反而显得在推销。删掉修饰，让数字自己说话。

| 原句 | 改后 |
| --- | --- |
| 更要紧的是，decode 每生成一个 token…… | decode 每生成一个 token…… |
| 把每个权重想成一个像素的亮度，差别就看得见了。 | 把每个权重想成一个像素的亮度。 |
| 这一层的误差是 99%，几乎什么都没存下。 | 这一层的误差是 99%。 |

同类：“惊人的”“恰恰”“偏偏”“真正的”“彻底”“一下子”“立刻就”“不过是”“这才是关键”“魔法在于”，以及段末用来收束情绪的短句。

### 4. 全局出处说明

正文不写对全文数据或代码来源的总括交代。这类句子是写给审稿人看的防御性说明，读者不需要。删掉；单个数字的出处在它出现的句子里就近标注。版本、commit、测量环境只放在文末参考与 `docs/<slug>-notes.md`。

例：“体积、速度与评测分数引自模型卡……”“真实权重的分布是本站在 X 上算的”“源码基于 vLLM v0.30.0”“以下数字均来自某论文”。

正文句子里顺带的版本号也一样删掉，例如“这个功能在 vLLM 里目前是关掉的：v0.30.0 的 `use_cascade_attention` 直接返回 `False`”改为“vLLM 没有启用这个功能：`use_cascade_attention` 直接返回 `False`”。“目前”“当前版本”这类时间限定一并删掉。

### 5. 口语与过度比喻

正文用书面语：定义写成“A 是 B”“称为”“即”，比较写成“A 为 x，B 为 y”。口语词和随手的比喻会让论述显得随意，也会引入正文没有定义的说法。必要的类比（如文中配图的灰度图）说明一次“以……类比”，之后直接用术语。

| 原句 | 改后 |
| --- | --- |
| 按有符号整数读是 −8 到 7，下文叫编号。 | 按有符号整数解释为 −8 到 7，本文称为编号。 |
| 同样盖住 −2 到 2，……格宽 0.016，0.37 只差 0.005 | 在同一区间 −2 到 2 内，……间隔约 0.016，0.37 的误差为 0.005 |
| 球上出现一圈圈断层 | 球面出现明显的色阶断层 |
| 浮点数像科学计数法，由指数和尾数组成 | 浮点数由指数和尾数组成 |
| 一个 outlier 仍然把整层的刻度撑粗 | 一个 outlier 仍会使整层的刻度变粗 |

章节标题同样书面化：用名词短语（“权重的分布”“decode 速度”），不用问句或口语（“真实的权重长什么样”“省下的字节换来什么速度”）。开头段写定义、目的和一个代表性结果，例如“量化是用更少的 bit 存储模型参数，目的是减少显存占用、加快 decode。Qwen3.8-27B 用 BF16 存储是 51.8 GiB，INT4 量化后是 18.1 GiB。”

## 流程

1. 逐段读，列出命中的句子：位置（节标题 + 段首几个字）、类别、原句、改后。
2. 把清单交给用户确认，确认后再改文件。用户明确说“直接改”时跳过确认。
3. 只改命中的句子。不合并或拆分段落，不调整论点顺序，不改数字、公式、术语、图和代码。
4. 改完不加总结段，不写“本次修改了……”这类说明到文章里。

## 判断边界

- 一个冒号引出定义或列表是正常用法，不算卖关子；判断标准是冒号前那句话删掉后信息是否损失。
- 每篇允许开头一句点题，但不写成“X 只问一件事”的格式。
- 用户以后发现的新套路追加到对应类别或新增一类，附一组原句 → 改后。
