## 结构

回顾（FP32 天花板）→ **第二幕「单元自己到顶」**：wmma 讲透（每时钟 ×16，只拿到峰值的十分之一，瓶颈回到数据），mma.sync、三级缓冲、wgmma 快剪；幕尾整幕阶梯 → **第三幕「让搬运与计算同时跑」**：warp 特化（生产者 / 消费者、环形槽位）与 L2 的意外（只改 tile 发放顺序，480 → 740）讲透，提前归还、常驻 kernel 的回退、集群多播、TMA 写回快剪；幕尾整幕阶梯 → 各规模对比与功耗墙 → 未完成的工作，回到完整阶梯。

## 三栏画面

全片主体是固定的三栏，三栏由 `frames.js` 的同一帧驱动：

- **左：完整 kernel 代码**。当前执行行高亮（橙底），相对上一版的改动行标 +；换版本时旧代码淡出、新代码淡入；长代码只显示当前帧附近约 30 行，随高亮行定位。
- **中：数据布局**。缩小的 A / B / C、共享内存、寄存器，这一帧被读（橙）、在用（绿）、选中线程（蓝）、同一 warp（浅蓝）的格子，下方是内存地址条与“每读 1 个数做几次乘加”的计数；没有逐帧剧本的版本（wmma、mma、mma_async、wgmma、pipe、persist、cluster、tstore）画专用示意图。
- **右：SM 剖面**。调度器与 warp 圆点、FP32 / Tensor Core / LSU·TMA、寄存器、共享内存 / L1、L2、HBM；流动的通路为绿色流动虚线，瓶颈单元或通路为橙色（贯穿全片的瓶颈标记）。说明文字由讲解页 `hwState` 的说明改写为书面语体，并对齐文章的推算数字（2 路 bank 冲突、8.7 → 5.9 TB/s、naive_T 16 次访存）。
- **底部：成绩阶梯**，当前版本点亮；每幕最后一拍放大为整幕阶梯。

逐帧剧本取自 1.3 讲解页的交互版（`framesNaive`、`framesSmem`、`framesReg`、`framesVec`、`framesWarp`、`framesDbuf`、`framesWS`、`framesL2`、`L(v, regex)`、`hwState`、注入的各版源码）。`inference-study/tracker/pages/s1.3-matmul-flops.html` 现已改为静态文章页，交互版取自 Claude Code 的文件历史备份（2026-10-21，含 naive_T 16 次访存的修正）。

## 简化之处

- 中栏网格是 16 × 16 的缩小示意，参数沿用讲解页（naive / smem 的 block 为 4 × 4 线程，warp 示意为同一行 4 个线程，reg 的 block 为 8 × 8、每线程 2 × 2，TC 版本的 tile 与槽位同为示意）；真实参数写在页眉出处里。
- 底部阶梯与整幕阶梯的数字为 8192 阶实测；naive_T 为 4096 阶（8192 阶太慢未测）。
- 配音与字幕是同一份文字；配音为空的拍只看画面。
