## 全部台阶幕共用的约定

- **开场 = 改动**：每幕 0–1.0 s 是标题卡：左上 `.kit-chip`（版本名）+ `.kit-title`“第 N 步：改动”（改动名用 `.acc`），干净纸面，不放别的。标题之后缩到左上角常驻（缩小后字号仍 ≥ 32 px）或淡出，按画面定。
- **结尾 = 问题**：幕的最后一句讲这一版的问题，画面在这一版自己的画面上贴 `.k-bottleneck` 橙色“瓶颈”标签，停到幕尾。下一幕从干净的标题卡开场（直切，不做交接动画）。s10 最后一句是结果，不贴瓶颈；s11 是收尾。
- **右上进度条**：`.kit-meter` 默认位置（brand.css），标签“8192 阶 · BF16 · TFLOPS”，满刻度按 cuBLAS 781.86（填充比例 = 值 / 781.86），右端刻度标“cuBLAS 781.86”。每幕开场显示上一版的值，在“实测”那句更新到本版。各版的值：wmma 93.3 → mma 269 → 三级缓冲 309 → wgmma 484 → warp 特化 480（8192 阶不变，另标 4096 阶 481 → 635）→ tile 分组 740 → 集群 757 → TMA 写回 777.6。
- **硬件塔**（`kitTower()`，需要时才用）：容器放在右侧 `left:1180px; top:300px; width:640px; height:620px`，全片同一位置，换幕时观众认得出。数据块用语义色小方块（A 蓝、W 黄、结果紫），沿真实路径移动。
- **矩阵与 tile 图**：A 蓝、Wᵀ 黄、C 紫，按比例；8192 阶 C 按 128 × 256 切成 64 × 32 个 tile（s07、s08 用同一张 tile 图，位置相同，s08 只改发放顺序）。
- 硬规则同上：字 ≥ 28 px；开场只有一样东西；同一时刻最多两个主体；部件在那句配音开始时进场；代码框最多 4 行；底部 150 px 留给字幕；数字只用 narration 与下面列出的。

## 各幕画面要点（每句一拍）

### s04 第 2 步：换位存放与 mma.sync（chip `mm_mma`）
1. 共享内存一块：8 行 × 8 个 16 字节块（一行 128 字节 = 32 个 bank 全部），块按所在 bank 组着色。
2. ldmatrix 读 8 行的同一块：不换位时 8 个地址叠在同一组 bank，轮数计数 1 → 8。
3. 换位动画：第 r 行第 c 块滑到 c ⊕ r（先单独演示一行，再其余一起），形成对角线；再读一次：8 组 bank 各 1 个请求，1 轮。
4. 硬件塔：L2 → 共享内存直达（cp.async，绿），旧的经寄存器折返划掉；共享内存 → 寄存器（ldmatrix）→ Tensor Core（mma.sync）。
5. 进度条 93.3 → 269，标“2.9 倍”。
6. 时间线一轨：发拷贝 → 等待（灰）→ 同步 → 计算；Tensor Core 一轨大段空闲；贴“瓶颈”。

### s05 第 3 步：三级缓冲（chip `mm_mma<3级>`）
1. 共享内存 3 个槽位的环（或三格），拷贝提前两块发出。
2. 时间线两轨：拷贝与计算重叠，三个块（计算中 / 已到 / 在途）三色与槽位同步轮转；标“每槽 32 KB，共 96 KB”。
3. 进度条 269 → 309，标“+15%”。
4. 指令体积：一条 mma.sync = 16 × 8 × 16 = 2048 次乘加的小长方体；“满载需每 SM 每时钟发一条”。
5. 进度条上约 300 处一条横线“mma.sync 止于约 300 ≈ 峰值的 1/3”，贴“瓶颈”。

### s06 第 4 步：TMA 与 wgmma（chip `mm_wgmma`）
1. 层级：thread → warp → **warpgroup（4 个 warp，128 个线程点 4 × 32）** → block。
2. TMA：硬件塔上一整块（已换位的条纹）从 L2 落到共享内存，只有一个线程点发出。
3. mbarrier：字节计数条 0 → 32 KB，满后 warpgroup 的点由灰变绿。
4. 体积对比：wgmma m64n128k16（131072 次）与 mma.sync m16n8k16（2048 次）两个长方体按体积并排，“64 倍”；塔上共享内存 → Tensor Core 越过寄存器。
5. 进度条 309 → 484，标“1.6 倍”。
6. 一个 warpgroup 的时间线：发 TMA、等待、计算交替，计算段之间有空隙；贴“瓶颈”。

### s07 第 5 步：warp 特化（chip `mm_wgmma_ws`）
1. 3 个 warpgroup 方框：生产者（0 号，发 TMA）+ 两个消费者（1、2 号，计算）。
2. 4 个槽位，每个两盏灯 full / empty，循环点亮。
3. 两个消费者的时间线交替占用 Tensor Core，空隙被对方填满。
4. 进度条：4096 阶 481 → 635（小字标注在条旁），8192 阶停在 480 不动。
5. 8192 阶的 C 切成 64 × 32 个 tile 的图；按行发放时一轮 132 个 tile（紫）横跨约 4 行、全部 32 列；Wᵀ 边条全部点亮；一根容量条：W 128 MB 对 L2 50 MB 刻线，溢出部分标橙；贴“瓶颈”。

### s08 第 6 步：tile 分组发放（chip `wgmma_l2`）
1. 同一张 tile 图（s07 同位置）：一轮的 132 个 tile 从“4 行 × 32 列”收拢成“16 行 × 约 8 列”。
2. 工作集条：136 MB → 65 MB（A 8 → 32 MB，W 128 → 33 MB），L2 50 MB 刻线。
3. 一块 W 读进 L2，随即被一列上的 16 个 tile 读取（16 条细箭头同时）。
4. 两组对照数字：显存读取 6.6 GB → 1.3 GB；L2 命中率 48% → 79%（同一基线的两根条）。
5. 进度条 480 → 740，标“1.54 倍”。
6. 每个 block 各自从 L2 读整块 W：132 条从 L2 出来的线；贴“瓶颈”。

### s09 第 7 步：集群与 TMA 多播（chip `wgmma_cluster`）
1. tile 图上相邻两行、共用同一块 W 的两个 tile 框成一个集群（图是转置画的，画面上左右相邻）。
2. 两个 SM 框进一个集群框；L2 里一块 W 分前后两半，各由一个 block 发出，箭头分叉写入两边的共享内存（多播）。
3. 每 block 每步 L2 读取 48 KB → 32 KB（两根同基线条）。
4. 常驻 kernel：132 个 block 循环领取 tile（一个 block 依次领 3–4 个 tile 的小动画即可）。
5. 进度条 740 → 757，标“cuBLAS 的 96.9%”。
6. 写回：一个线程的 64 次零散 4 字节写入（64 个小点逐个飞向显存），这段时间 Tensor Core 一轨空闲；贴“瓶颈”。

### s10 第 8 步：TMA 写回（chip `wgmma_tstore`）
1. 塔上紫色结果路径反向：寄存器 → 共享内存（换位写入）→ 一条 TMA 整块写出到显存；旧的零散写划掉。
2. 时间线：写回段移到 TMA 一轨，与下一块的计算重叠。
3. 共享内存占用条：结果区 64 KB + 缓冲，由 4 级减为 3 级（共 208 KB，上限 227 KB 刻线）。
4. 进度条 757 → 777.6，几乎碰到 cuBLAS 刻度，大字“99.5%”。不贴瓶颈。

### s11 功耗墙与总结（chip 可以不用；标题“持续运行：700 W 功耗墙”）
1. 时钟表或一根时钟条：1830 → 约 1360 MHz，旁标“700 W”；手写版与 cuBLAS 两条线一起降。
2. 同一刻度四根条：989（规格）、735（1360 MHz 下的峰值）、682（手写版持续）、681（cuBLAS 持续）；标“都用到 93%”。
3. 能效：每次浮点运算 1.05 pJ 对 0.81 pJ，两根同基线条，标“多 29%”。
4. 总结三行由下往上：执行单位 warp → warpgroup → cluster；数据：寄存器中转 → TMA 整块搬运；指令：wmma → wgmma。
5. 首尾呼应：开场的 2048 个点阵回来，93% 点亮（teal），其余灰；最后一句停留到结束。
