## SHOTS（每句配音 → 画面要讲清的原理）

在第二版场景（git 中当前的 compositions/sNN.html）基础上改：保留能用的原理画面，删速度大屏，按新句子补原理画面，全部节拍改到新秒数。

### s01 开场（20.86 s）
1–2 句不变（左右并排填充 + 计时、同一批 Tensor Core）。第 3 句改：不要 989 对 93.3 的大横条；画一条 Tensor Core 的忙闲条（横贯画面，约 1400 px）：9% 是 teal“在算”，其余 91% 灰色斜纹“等数据”，大字“等数据”。第 4 句：居中大耗时条 + 一条从“显存”到“Tensor Core”的数据通路线，字“八步，改的都是这条路”；最后 1.5 s 耗时条缩回右上角。

### s02 wmma（29.86 s）
1 一个 warp 的 32 个线程点合成一个 16×16×16 立方体（保留第二版）。
2 塔：数据块走 显存 → L2 → 寄存器 → 共享内存 → 寄存器 → Tensor Core，两次寄存器处标橙（保留，左侧路径清单保留）。
3 新：共享内存放大成 32 个 bank 的一排格子；同一轮 32 个线程的地址落进 bank：落在不同 bank 的一轮同时完成（绿），两个地址撞同一 bank 时排成两轮（红），讲清“同 bank 排队”。
4 一行 64 字节 = 半排 bank；8 行的同一块叠在 2 组 bank 上，分 4 轮逐轮点亮（保留第二版的 4 轮动画）。瓶颈标签。
删：第二版的“只有 cuBLAS 的 12%”和两根对比条。

### s03 换位 + cp.async（31.93 s）
1 一行加宽到 128 字节 = 32 个 bank 一整排（8 组，每组 4 个 bank，每组 16 字节一块）。
2 8 行 × 8 块的网格，ldmatrix 读“同一块”= 一列：8 个地址都在第 0 组，红，“8 轮”。
3 每行按 c ⊕ r 滑动，第 0 块变成对角线，落在 8 个不同组，绿，“1 轮”（保留第二版动画；可写出 c ⊕ r，字 ≥ 32 px）。
4 塔：寄存器那段划掉，cp.async 由 L2 直接进共享内存（保留）。3 s 后耗时条缩短。
5 时间线：发拷贝 → 等完成 → 计算，Tensor Core 在等待段空闲（保留），瓶颈“等拷贝”。
删：“快 2.9 倍”。

### s04 三级缓冲（27.79 s）
1 显存 → 3 个槽位的环 → Tensor Core；先预取两块（保留第二版的真实移动）。
2 循环：算第 t 块时后两块在路上；算完的槽位立即装下一块；下方加一条两行时间线，拷贝条与计算条重叠，“等待被盖住”。3 s 后耗时条缩短。
3 一条 mma.sync = 小方块“2048 次乘加”；每个时钟一格，每格都要一条 mma.sync，外加 ldmatrix（另一种颜色）挤占发射；格子塞不满（保留并加上 ldmatrix）。
4 “峰值的 1/3”可保留为一行标注（不是大屏），瓶颈“指令太小”。

### s05 TMA + mbarrier + wgmma（37.41 s）
1 三个名字依次出现：TMA、mbarrier、wgmma（大字，左侧）。
2 TMA：一个线程点发一条指令，一整块矩阵落进共享内存并换位（保留）。
3 新：mbarrier = 共享内存里的计数器：TMA 的数据分批到达，计数器的字节数往上加（0 → 32 KB），计满变绿，计算方的等待解除、开始读。
4 wgmma：4 个 warp 组成 warpgroup；一条 wgmma 与一条 mma.sync 面积 64 : 1；操作数从共享内存直接进 Tensor Core（保留）。5 s 后耗时条缩短。
5 时间线：同一组线程 发 TMA → 算 → 发 TMA → 算，两块之间 Tensor Core 空着（保留），瓶颈标签。
删：“快 1.6 倍”。

### s06 生产者/消费者（37.54 s）
1 三条泳道：生产者只发 TMA；消费者 1、2 只计算（保留）。
2 新：一个槽位 + 两个灯：full（数据到了，生产者点亮，消费者等它）、empty（用完了，消费者点亮，生产者等它）；一块数据走一遍：生产者等 empty → 发 TMA → full 亮 → 消费者算 → empty 亮。
3 两个消费者交替，Tensor Core 那一条始终有活（保留泳道动画的 Tensor Core 行）。
4 一行小标注（≤ 36 px）：“4096 阶：变快　8192 阶：不变”；耗时条抖一下。不做 TFLOPS 大条。
5 tile 图：按行发放，同时运行的 132 个 tile 约 4 行 × 32 列，读整个 W；容量条 128 MB 对 L2 50 MB；W 的块被后来的数据挤出 L2（保留第二版 tile 图与容量条，加“挤出”的动作）。瓶颈“L2 装不下”。

### s07 发放顺序（25.05 s）
1 tile 图：132 个 tile 按新顺序重排成 16 行 × 约 8 列（保留）。
2 新：按行发放时，共用同一块 W 的两个 tile 编号相差 32：标出 tile 0 与 tile 32，时间轴上相隔很远，中间 W 被换出 L2（W 块从 L2 框里被挤掉）。
3 分组后它们编号相邻、同时运行：W 读进 L2 一次，扇出给 16 个 tile（保留第二版扇出）。
4 “显存读取 6.6 GB → 1.3 GB”一行（数据量是原理的证据，可保留一根缩短的条），耗时条同时缩短。删“+54%”。

### s08 集群 + 多播（30.62 s）
1 新：两个 block（两个 SM）各自的共享内存，框成一个集群，中间一条双向箭头“可访问彼此的共享内存”。
2 两个 block 共用同一块 W：W 分前后两半，block 0 搬前半、block 1 搬后半（保留）。
3 TMA 多播：从 L2 读一次，分叉写进两个 block（保留）；旁边一行“每 block 每步从 L2 读：48 KB → 32 KB”（两根短条）。3 s 后耗时条缩短。
4 写回：每个线程零散写显存 64 次，期间 Tensor Core 不发 wgmma（保留），瓶颈“写回”。
删：“cuBLAS 的 96.9%”与对比条。

### s09 TMA 写回（25.27 s）
1 结果从寄存器换位写进共享内存（保留，换位可以用对角错开的小格表示）。
2 一个线程发 TMA，整块写回显存；时间线上写回与下一块计算重叠（保留）。
3 新：共享内存预算条（上限 227 KB）：4 级缓冲 + 64 KB 结果区超出上限（红）→ 减为 3 级，共 208 KB，放得下。
4 耗时条缩短到 1.41；主画面一行“1.41 ms · cuBLAS 的 99.5%”（≥ 48 px），不做对比条。

3 新：阶梯每一行右侧换成这一步的原理名：第 1 版“用上 Tensor Core”、第 2 版“不冲突、不绕路”、第 3 版“提前搬”、第 4 版“搬大块”、第 5 版“分工”、第 6 版“少读显存”、第 7 版“共享读取”、第 8 版“异步写回”，随配音逐行点亮。
