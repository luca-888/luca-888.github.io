# v6 大纲：Tensor Core 在等什么

目的：教原理。每一步只教一个机制：为什么会卡，新方法为什么能解决，用动画演示。
进度只靠右上角的速度条（cuBLAS = 100%），不念出来。证据和数字留在 CONCEPT.md 与文章里。
目标时长约 5 分钟。

**全片的骨架是一张存储层级图（地图）：**

> 显存 → L2 → shared memory → 寄存器 → Tensor Core

结果再从寄存器写回显存。每一步都回到这张图：点亮这一步作用的那一层，演示机制，速度条前进一格。

保留的数字只有这几个：32 个 bank、8 路冲突 → 1 轮、mma.sync 只有 wgmma 的三分之二、一块 W 被 16 个 tile 共用、共用的数据只从 L2 读一次。

## 开场：Tensor Core 在等数据

- **机制：**
  - Tensor Core 一条指令算一整块矩阵乘，比普通计算单元快十几倍。
  - 它只能算已经送到手边的数据。数据要从显存经过 L2、shared memory、寄存器，一层层送进来。
  - 最直白的写法里，Tensor Core 大部分时间在等数据。后面七步，都是让它少等。
- **动作：**
  - 芯片放大到一个 SM，再放大到 Tensor Core，一拍吃掉一整块。
  - 地图从显存一层层搭到 Tensor Core。
  - 一块数据沿地图慢慢流上来，Tensor Core 闪一下就停，空转等下一块。
  - 屏幕列出七步的标题，每个标题挂在它作用的那一层旁边。

## 1　swizzle：把数据错开存，避免 bank 冲突

作用层：shared memory → 寄存器

- **机制：**
  - shared memory 分成 32 个 bank，同一拍每个 bank 只能送出一份数据。
  - 矩阵按行存，Tensor Core 要的片段却是竖着跨好几行取。行宽恰好是 bank 宽度的整数倍时，这几行落在同一个 bank 上，只能排队一轮轮读，最坏要 8 轮。
  - swizzle（原意“搅乱”）：存的时候，每行按行号把数据块换个位置。竖着读时，各行落进不同的 bank，一轮读完，也不多占空间。
  - 读的一方随之改用 ldmatrix，每个线程自己算换位后的地址。
- **动作：**
  - 32 根 bank 柱排成一排。
  - 8 行数据落下，全堆在同一根柱上，逐个排队送出，计数显示“8 轮”。
  - 换位后 8 行斜着落成对角线，一拍同时送出，显示“1 轮”。

## 2　cp.async：搬运不再经过寄存器

作用层：L2 → shared memory

- **机制：**
  - 原来搬一块数据，线程先把它读进寄存器，再写进 shared memory。数据到达前线程只能干等，搬完才能开始算。
  - cp.async 让数据从 L2 直接进 shared memory，不经过寄存器。指令发出后，线程立即去做别的事。
  - 再配几块缓冲轮换使用：算这一块的时候，下一块已经在路上。
- **动作：**
  - 地图上原路径绕经寄存器一圈，然后变成一根直达箭头。
  - 下方时间线上，“搬”和“算”从一前一后排队，变成上下重叠。

## 3　wgmma：换一条更大的指令

作用层：shared memory → Tensor Core

- **机制：**
  - 前面用的 mma.sync 一条只算一小块，操作数要先搬进寄存器。即使数据从不缺，它每个周期也只能做到新指令三分之二的工作。
  - Hopper 的 wgmma 由 4 个 warp 一起发出，一条算一大块，操作数直接从 shared memory 读，省掉搬进寄存器这一步。
  - 配套两样新硬件：
    - TMA：一条指令搬一整块数据，搬的同时完成 swizzle；
    - mbarrier：数据到齐时通知计算方。
- **动作：**
  - Tensor Core 前面排着一串小块指令，被一整块大指令替换。
  - 地图上“shared memory → 寄存器”这一段淡出，箭头从 shared memory 直接指向 Tensor Core。
  - TMA 把一整块推进 shared memory，mbarrier 的计数格填满后亮灯。

## 4　warp specialization：一组专门搬，一组专门算

作用层：整条供给线（时间上）

- **机制：**
  - 上一版同一批线程既搬又算。每算完一块，大家要一起同步，下一块才开始。Tensor Core 在块与块之间空转。
  - 分工：一组 warp 只负责发 TMA 搬运（producer），另外两组只负责计算（consumer）。双方用 mbarrier 交接：数据到了，计算方开工；用完了，搬运方补上。
  - 搬运永远提前几块，计算方不再等。
- **动作：**
  - 两条泳道：上面搬运一直往前跑，下面计算接连不断。
  - Tensor Core 时间线上的空隙一格格被填满。

## 5　tile 分组：让共用的数据趁热复用

作用层：显存 → L2

- **机制：**
  - 大矩阵切成很多 tile，同时有一百多个在算。同一列的 tile 要用同一块 W。
  - 按行顺序发放时，共用 W 的 tile 前后相隔很久才开始。等后一个用到时，这块 W 早被挤出 L2，只能再从显存读一遍。
  - 改成分组发放：每 16 行一组，组内按列发。共用 W 的 tile 几乎同时开始，一块 W 读进 L2，立刻被 16 个 tile 用掉。
- **动作：**
  - tile 网格按行一个个亮起。W 块进入 L2，又被后来的数据挤出去，显存箭头反复闪。
  - 换成分组顺序后，一列 16 个 tile 同时亮。一块 W 进入 L2，分出 16 根线，显存箭头变细。

## 6　cluster 多播：读一次，两个 SM 共用

作用层：L2 → shared memory（跨 SM）

- **机制：**
  - 相邻两个 SM 算相邻的 tile，要同一块数据，原来各自从 L2 读一遍。
  - Hopper 的 cluster 把两个 SM 编成一组。TMA 多播把共用的数据从 L2 读一次，同时写进两个 SM 的 shared memory。
- **动作：**
  - 两根从 L2 出发的箭头，合成一根后分叉进入两个 SM。

## 7　TMA store：写回时不停算

作用层：寄存器 → 显存

- **机制：**
  - 算完一块要把结果写回显存。原来每个线程零零散散写很多次，这段时间 Tensor Core 不干活。
  - 改为：计算方把结果先放进 shared memory，由 TMA 一条指令整块写回，计算方马上接着算下一块。
- **动作：**
  - 写回路径从寄存器直写的一堆细箭头，变成经 shared memory 的一根粗箭头。
  - 时间线上计算之间的写回空隙消失。

## 收尾：Tensor Core 不再等

- **机制：**
  - 回看地图：前四步在 SM 内部，让读取不冲突、搬运不占线程、指令更大、搬与算分工；后三步在 SM 之外，让显存和 L2 少读，并把写回藏进计算。
  - 一句总结：矩阵乘法的快慢，取决于 Tensor Core 有多少时间在等数据。
- **动作：**
  - 地图七处依次点亮。
  - 速度条走到与 cuBLAS 齐平。
  - 一块数据流畅地沿地图流上来，Tensor Core 持续亮着。
