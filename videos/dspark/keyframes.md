# DSpark 视频关键帧（待校对）

静态关键帧，不含动效；每帧一个点，右下角编号。画面在 `keyframes.html`，`node keyframes.mjs` 导出 `keyframes/kNN.png` 与总览 `keyframes/sheet-1..3.png`。配色、字体与版式沿用 `videos/vllm-distributed/v3/film3.html`，横版 1920 × 1080。

贯穿全片的视觉元素是 token 色块，状态固定：黑色为 target 自己的输出，紫框空心为猜的，蓝色为送去验证，绿色加 ✓ 为接受，红色加 ✗ 为拒绝，灰色斜纹为不验。例句是一句回答 “Of course, let me look”。

| 帧 | 章 | 这一帧要说的点 | 数据 / 来源 |
| --- | --- | --- | --- |
| K01 | 封面 | DeepSeek V4 · DSpark：线上的 speculative decoding 怎么做；下方一轮的 token 条过渡到 K02 | 示意 |
| K02 | 问题 | 每生成一个 token 整个模型算一遍；先猜几个、一次验完 | 示意 |
| K03 | 上一代 | MTP-1 每轮只猜 1 个；固定多猜时，猜错的 token 占掉别的请求的位置 | MTP-1 为论文所述的原线上方案；格子数为示意 |
| K04 | 起草 | 两种 drafter：一个个猜（猜 4 个跑 4 次）与一次全猜（跑 1 次） | 论文 §2.2 |

## 影片 v5：并行 backbone 与 Markov head 的真实结构（2026-10-03）

用户对 v4 的反馈：EAGLE-3 的对比不该插在中间；并行 backbone 和 Markov head “还是有点抽象，或者说过度简化了”。改动：

- 新增“并行 backbone”一幕（第 3 幕）：target → context（target 中间几层的 hidden state）→ 一个小 Transformer；输入是上一个确定的 token 加 3 个 mask，每层这些位置互相看、也看 context，输出每个位置对整个词表的打分。依据：论文 §2.2 与 vLLM `qwen3_dflash.py` / `qwen3_dspark.py`。
- 新增“Markov head 的结构”一幕（第 5 幕）：前一个 token → 查 W₁（词表 × 256）的一行 → 256 个数 → 乘 W₂（256 × 词表）→ 对每个 token 的加分 → 加到 backbone 的打分上 → 采样 → 成为下一位的“前一个 token”。原来的“一张表”改为紧接其后，说明两个矩阵乘起来就是那张表。
- 与 EAGLE-3 的三幕（起草方式、接受率曲线、对照表）合到线上结果之后、小结之前。

共 16 幕、约 215 秒。渲染：`node film.mjs film-main.html build/dspark-v5.mp4 --draft --fps 30`。
