# 知乎文章导出与发布

产出可连贯阅读的知乎文章。把无法迁移的交互降级为静态图、静态表格或简短正文；保留代码的可复制性与数据的真实性。与用户交流保持简短，交付文件或文章链接即可。

## 根据当前请求推进

- **导出**：读取 [静态导出](references/export.md)，生成 Markdown、PNG 和离线 HTML 预览。
- **导入、补图或发布**：读取 [网页自动化](references/web-publishing.md)，使用当前可用的浏览器或电脑操作工具。优先复用已登录会话。
- **已有导出稿**：直接校验并生成图片定位清单，不重复导出或重新测量性能。
- 用户明确要求“发布到知乎”时，完成检查后直接执行发布并验证文章链接；仅要求导出、导入或草稿时，执行到该阶段。未指定公开发布时默认保存草稿。更新已有文章须能确定目标文章，避免误写另一篇。

只修改本次导出产物和已指定的知乎草稿/文章。若其他任务正在编辑或部署博客，使用源码快照与独立临时预览，不更改原项目、Git 状态、依赖或正在运行的服务。

## 交付与图片定位

常规产物：

```text
<export-dir>/
  <article>.md               静态正文，图片使用 assets/ 相对路径
  <article>.html             离线预览，可内嵌 PNG
  assets/                   图表、公式等 PNG
  <article>-web-import.md    网页导入稿：图片改为唯一文字占位符
  upload-map.json            图片在正文中的顺序、上下文、路径和校验值
```

运行附带脚本（路径相对于本 skill 目录）：

```bash
python3 scripts/prepare_uploads.py /absolute/export-dir/article.md
```

可用 `--source /absolute/source.md` 验证导出前后 fenced code 内容一致。脚本只写入导入稿与清单，不改源 Markdown。

**自动化优先导入 `-web-import.md`。** 其中 `【配图 ZHIMG-001｜…】` 等文字可精确定位，避免出现难以定位的“上传失败”图片块。图片顺序以清单为准，不按文件名字典序上传。

HTML 中的 Base64 图片只保证离线预览可见，不能据此声称知乎已接收图片。浏览器也不能通过导入 Markdown 读取本机 `assets/` 文件夹；通过知乎图片按钮或上传控件逐张上传实际文件。

## 完成标准

- 导出无未展开的组件占位符、失效的交互说明或空白图；代码保持完整，图表与正文数据一致。
- 网页端标题填入标题栏，正文没有重复的文章标题。
- 每一图片占位符都已替换，图片上传成功；代码仍为代码块，章节顺序正确。
- 发布前检查正文无 `ZHIMG-`、`上传失败`、残留本地路径和误插入的文件名。
- 保存/发布后重新读取页面，确认内容保留，记录实际草稿/文章地址。
- 未进入知乎验证时，只报告“已导出/本地检查通过”，不报告“导入成功”或“已发布”。
