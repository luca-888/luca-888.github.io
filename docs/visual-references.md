# 技术图表参考

## 用户确认的优先方向：colah / Distill

用户明确认可 colah 与 Distill 的插图风格，后续正文技术插图优先参考以下表达原则。借鉴重点是如何解释概念，具体配色与构图随主题选择。

- **图形就是解释**：用长度、面积、分布和空间关系表示数学量，读者能从图中看出变量如何相乘、累加或变化；量化图形的比例必须与数值一致。
- **保持视觉对应**：同一变量、分布或对象在连续图中沿用颜色与标记；对照图尽量只改变需要比较的因素，坐标尺度变化须说明。
- **图文连贯**：图靠近对应论述，从具体例子推进到一般关系；直接标注关键对象和差异，减少在图例、正文与图之间来回查找。
- **克制而清楚**：充分留白、清晰轮廓与少量语义色，数学结构优先。色彩可以鲜明，但应承担区分对象或强调关系的任务。
- **有解释价值才交互**：可调参数、轨迹或联动高亮应回答明确问题；重要条件、默认示例和结论直接可见，不把全部内容藏在悬停或切换中。
- **原图与自绘区分**：优先引用作者提供的原图或源文件，注明作者与出处；自绘图保留本站术语、KaTeX 和浅色/夜间模式，记录参考来源。

本文集中记录本站技术图表的通用设计原则与官方案例。案例用于参考信息组织方法，具体配色与版式按内容选择；以下观察不代表 OpenAI 的统一设计规范。

## 通用原则

- 先明确图表要回答的问题，让读者先看到核心关系或结论，再读执行顺序、分组与细节。
- 用构图、对齐、留白、字号和字重建立层次。主流程与关键结果突出，辅助状态、精度和源码名分层标注；内容过密时拆图或使用逐步交互。
- 颜色用于区分阶段、类别、状态或强调关键关系，同一图表中的含义保持稳定，并配合文字、位置或形状表达。
- 配色、明暗、填色面积与线条强度按内容选择，不限定固定色表或低饱和风格。文字与背景保持足够对比，大面积填色应帮助分组和定位，避免干扰阅读。
- 按实际展示尺寸保证文字清晰、节点和标签对齐、箭头关系明确，避免遮挡与裁切。通过布局容纳内容，不靠缩小整图解决拥挤。
- 关键内容直接可见，详细信息同时提供可读文本，不只依赖悬停；图例、控件、结果和简短说明靠近对应图形。
- 自绘图与表格兼顾浅色和夜间模式；引用的官方原图保留原有标签、配色与连接细节。

## 表格组织

- 用表头、分组底色、间距与分隔线组织比较关系，突出关键行列或数值；颜色、字重与边线强度按信息层级选择。
- 数字及数值表达式右对齐，文本列左对齐，表头与对应数据同向对齐；数字使用等宽字体和 `tabular-nums`，同列同类数值的小数位数保持一致。
- 多指标按语义分组，组标题居中，单位集中标在对应表头。说明贴近表格，表内代码不加灰底胶囊。
- 表格整体居中，宽度随内容，字号和单元格间距按实际阅读尺寸与信息密度调整。

## 官方案例：表格

- [GPT-4.1 · Appendix](https://openai.com/index/gpt-4-1/#appendix)：表头和 benchmark 名称加粗，数字保持普通字重；新模型家族的连续三列使用极浅蓝底和细蓝轮廓，其余部分以白底、深色字、浅色横线呈现。颜色强调被讨论的对象，而不是给每一类数据都铺实色。
- [GPT-4.5 · 附录](https://openai.com/zh-Hans-CN/index/introducing-gpt-4-5/#fu-lu)：主要依靠表头字重、行列对齐和浅色横线组织信息；正文白底，脚注较小且弱化，没有彩色表头。

## 官方案例：技术图

- [Harness engineering](https://openai.com/index/harness-engineering/) 的分层架构图使用深色轮廓、对齐的节点、分组容器和清楚的依赖方向；用空间安排区分内外关系。
- 同文的 observability 数据流图以黑白结构为主，绿色集中标出 Codex 的反馈路径。可以直接看到主数据流与反馈路径的区别，无需把所有节点涂成不同的颜色。
