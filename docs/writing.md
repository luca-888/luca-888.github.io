# 写文章

写新文章、改稿、成稿自查时读这一篇。术语统一写法见 [术语表](terminology.md)。

### 写一篇新文章

1. **判断是否需要实验。** 需要硬件时先说明配置并与用户确认获取途径（见 [GPU 实验规范](gpu-experiments.md)）；不需要就直接说明。
2. **调研。** 优先读提出者的论文、官方文档与源码，以及有一手经验的个人或团队 blog，交叉核对；只把实际读过的内容标为已读。读源码用 `~/Documents/ChatGPT/reference-repos/` 下的浅克隆（vLLM、SGLang 等，`./sync.sh <name>` 更新），不要在本仓库内 clone；在 notes 里记录所读的 tag 或 commit。
3. **提交参考方案，等用户确认后再写正文。** 方案包括：按重要程度排序的参考清单（标题与链接、作者、阅读状态、重要程度、用于哪一章）、文章主线、章节提纲、待核实问题。用户提问或未回复不算确认。调研时必查两项：**现状变化**（论文或早期设计在当前版本中是否已被修改、替换或删除，以源码与 release 为准）和**相关系统对比**（同类系统的不同做法与公开的反对意见）。
4. **先草图，后精画。** 列出每张核心图要回答的问题并给出粗稿，用户认可方向后再精画；自绘图优先复用 `src/figure-kit.tsx` 的图元。
5. **记录。** 参考清单、阅读要点、分歧与确认范围写入 `docs/<slug>-notes.md`。确认后常规补充出处无需重新确认；新增核心来源、改变主要结论或大幅调整方向时再确认一次。

错字、措辞与局部样式修改不走以上流程。

### 写作

- **每篇独立成篇。** 就地交代所需背景、符号与实验条件，不写“上一篇 / 下一篇”，不把关键解释交给站内链接。用户明确要求连载时例外。
- **精简、先给结论。** 每节围绕一个明确的论点展开，直接解释概念、机制与结果；避免重复提醒和防御性措辞，必要的适用条件就近说一次。不用“更要紧的是”“值得注意的是”这类强调或排序的过渡语，也不用“X 问的只是一件事：……？”这类先铺垫再揭晓的设问，直接陈述事实。（2026-10-06 用户要求）
- **科普定位。** 文章是科普，不是测试报告：每个实测结论给一个代表性数字和一句原因，不罗列各档并发与配置；“单次测量”“不下结论”“未复现也未反驳”这类限定不写进正文，完整矩阵、方法与误差留在测量记录。（2026-10-01 用户要求）
- **段落与列表。** 推理、因果与演化写成短段落（两到四句），不拆成要点；并列内容（定义、对照的两种情形、图中各行的解读、步骤、配置分档）才用列表或表格。避免整块长文，也避免把论证切碎成 bullet。
- **区分来源。** 分清来源结论、实测结果与自己的分析；用自己的主线组织，不拼接他人文章。正文非必要不挂引用链接，出处集中在文末参考；不点名就分不清来源的结论（如某篇论文的实验数字），在句中写明来源（“StreamingLLM 的实验中”），同样不挂链接。正文不写“数字均来自某论文”“源码基于某版本 / commit”这类全局交代，版本与 commit 只放在文末参考和 notes 里。（2026-10-05 用户要求，2026-10-10 更新）
- **术语。** 默认读者熟悉常见术语，直接用英文或缩写，不附中文译名。统一写法见 [术语表](terminology.md)，写作前查阅；用户指定新用词时同步更新。
- **代码。** 只保留理解实现所需的部分，省略 import、环境与入口；简短调用写在一行。
- **实验数据。** 使用真实测量，正文只注明显卡型号；benchmark 规则、计时口径、环境细节留在测量记录里。演示数据须标明。
- **成稿自查。** 写完后逐句过一遍，只改下面四类问题，不改句式和段落：（2026-10-03 用户确认）
  - 文章自己引入的词（如“转折点”“重要 channel”）在第一次出现时定义；术语表只管通行术语，不管这一类。
  - 一个概念全文只用一个词；必须换词时（如“步长”与 scale）就地说明两者的关系。
  - 数量与比较写明两端和基准：写“缩小到 1/s”“BF16 是 14.6，NVFP4 是 38.6”，不写“缩小了 s 倍”“从 14.6 升到 38.6”。
  - “它”“这”离所指超过一句，或前面有两个可指的名词时，换成名词。
- **去 AI 腔。** 不写四类套路：先卖关子再揭晓（“X 只问一件事：”“问题出在两处：”）、路标句（“下文从……讲起”“下面两节分别……”）、刻意的戏剧感（“更要紧的是”“几乎什么都没存下”）、全局出处说明。成稿自查之后，用 `de-ai-edit` skill 单独改一遍，交给不带写作上下文的 subagent 执行。（2026-10-06 用户要求）
- **语体。** 书面、正式：定义用“是”“称为”“即”，比较写“A 为 x，B 为 y”；不用口语词和随手的比喻，必要的类比说明一次。开头段给定义、目的和一个代表性结果。（2026-10-06 用户确认，以 [LLM 量化](../content/llm-quantization.md) 为范例）
- **标题。** 章节标题简洁、正式，用名词短语，不用问句或口语。
