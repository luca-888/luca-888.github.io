# GPU 实验规范

## 获取途径

- 用户有租用 RTX 4090 的资源和 Modal 账号（可获取 H100、B200 等）。具体型号与方式以当前任务中用户的确认为准；会话内已确认的可直接沿用。
- 不因本地缺少设备而擅自降级硬件、缩减实验或用模拟数据替代实测；受限时先与用户协商。

## 高价值 GPU 与多卡

适用于 H100/H200、B200/B300、RTX PRO 6000 等高价值 GPU，以及任何多卡配置。

- **申请前一次性做完整计划**，写入实验记录：目标、GPU 型号与数量、获取途径、容器数量与并发、完整测试矩阵、依赖与输入、正确性检查、预期输出、完成条件。设备探测和试运行也计入计划，不以“先试一下”提前占卡。
- **先在无需目标 GPU 的环境完成**代码、镜像依赖与可做的验证；同一硬件上的测试尽量集中在一次申请、一次远端调用中完成。
- **时间与费用预估**：区分准备/构建、排队、GPU 占用、结果回传，给出总时长与 GPU 占用上限；费用按执行前查询的当前费率计算，含 CPU、内存、存储等，注明币种、范围、预算上限与不确定项。无法确定的不当作零。
- **执行约束**：超时、容器上限、并发与重试限制与计划一致；异常或触及时间/预算上限时停止并保存已有结果，不自动重跑整套矩阵。补测前更新剩余测试、时间与费用；超出已授权范围先协商。
- **收尾**：完成或中止后立即释放资源并核查状态，记录实际占用时间与可获取的费用，区分估算与实际账单。写作与等待期间不保持 GPU 占用。

## 测量记录

- 原始数据、脚本、环境（显存、软件版本、驱动、CPU 等）与测量方法保留在实验记录或 `public/measurements/` 中。
- 正文只注明显卡型号，不写 benchmark 规则、计时口径和 profiler 采集步骤。
