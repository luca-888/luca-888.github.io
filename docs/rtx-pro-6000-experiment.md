# RTX PRO 6000 八卡拓扑：一次性实验计划与记录

## 目标与资源

为《RTX PRO 6000 多卡拓扑：从硬件连接到通信性能》采集真实设备树、拓扑矩阵、NCCL topology XML 与通信数据。H100 不在本轮范围内。

- 获取：本机既有 Modal CLI / SDK，`gpu="RTX-PRO-6000:8"`，单容器、同一物理机八卡、一次远端调用。
- 资源：CPU 8 core、主机内存 16 GiB；`max_containers=1`、`min_containers=0`、不并发发起调用、不 detach、不持久部署。采用生成器逐步回传，Modal SDK 不支持为生成器配置 retries，本地也不重试调用。
- GPU 名称和数量、设备可见性先在同一调用内核验。型号/数量不符、八卡申请失败或无法满足实机拓扑实验条件时，记录原因并停止，不自动降级或换型号。
- 本地完成脚本语法与参数检查；镜像内预装固定版本工具并在 CPU 构建阶段编译，避免占用 GPU 安装依赖。
- 固定依赖：CUDA 12.8.1 devel / Ubuntu 24.04；Python 3.10 与本机 CLI 小版本系列一致；NCCL wheel 2.27.7；nvbandwidth v0.9（commit `1aa9e818d0728c25c87e121d692d829db2239720`）；nccl-tests v2.17.9（commit `2535da805b34e96d1dc08be66289be1a6d57f5ad`）。CUDA 编译目标 `sm_120`。工具源码内存档完整版本，正文只保留有解释价值的硬件结构。

- 不自动重试或重跑全矩阵。必要补测单独列缺项、原因、时间与费用；超出本轮范围/预算时先协商。

- 成功标准：型号/数量正确、实机路径可解释、原始输出齐全、传输正确性通过、NCCL XML 可读且与 PCI BDF 对应、主要通信矩阵与代表分组测试有有效数据。部分失败不得记作完整成功。
